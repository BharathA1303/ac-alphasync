# AlphaSync Real — Deployment

Production deployment for **AlphaSync Real** — users connect their own real
broker accounts, the platform ingests their broker's live market data, and users
run **simulated** trades against that real data.

- **Domain:** `demo.alphasync.app`
- **Deploy path:** `/opt/apps/alphasync-real`
- **Compose project:** `alphasync-real` (explicit — never autogenerated)

Fully isolated from every other app on the server. Never touches any other
application's containers, networks, or volumes.

---

## 1. Folder structure

```
/opt/apps
├── alphasync-real/          ← this app
├── ...                      ← other apps (each isolated, untouched)
├── backups/  scripts/  shared/

/opt/apps/alphasync-real/
├── backend/                 # FastAPI source + Dockerfile   (build context ./backend)
├── frontend/                # React source + Dockerfile      (build context ./frontend)
├── docker-compose.yml       # project = alphasync-real
├── .env                     # real secrets (NOT committed)
├── .env.example             # template
├── deploy/                  # rollback state (last_good_images.env)
├── nginx/
│   └── demo.alphasync.app.conf   # host nginx site
├── logs/
├── uploads/
├── scripts/
├── deployment.sh
├── update.sh
├── rollback.sh
└── README.md
```

> In this repo the deployment lives under `deploy/alphasync-real/` and maps 1:1
> onto `/opt/apps/alphasync-real/` on the server. `frontend/nginx.internal.conf`
> is the **container-internal** nginx (proxies to the `backend` service); it is
> distinct from `nginx/demo.alphasync.app.conf`, the **host** nginx site that
> terminates TLS.

---

## 2. Isolation contract

| Resource   | Name(s)                                                        |
|------------|---------------------------------------------------------------|
| Project    | `alphasync-real`                                               |
| Containers | `alphasync-real-{frontend,backend,postgres,redis}`            |
| Network    | `alphasync-real-network` (dedicated bridge)                   |
| Volumes    | `alphasync-real-{pgdata,redis,uploads}` (named)              |
| Host ports | `127.0.0.1:3001→80` (frontend), `127.0.0.1:8001→8000` (backend) |

- **Postgres & Redis are internal-only** — no host port; reachable only inside
  `alphasync-real-network`.
- Host ports bind to **loopback** so only the host nginx reaches them.
- No `--remove-orphans`, no `docker system/volume/network prune`. Cleanup is
  limited to `docker image prune -f` (dangling images only).

---

## 3. Request flow

```
Browser ──HTTPS 443──> host nginx (demo.alphasync.app)
                          ├─ /            → 127.0.0.1:3001  (frontend)
                          ├─ /api/ /ws/   → 127.0.0.1:8001  (backend)
                          └─ /uploads/    → 127.0.0.1:8001

Inside alphasync-real-network:
  frontend nginx ─/api,/ws,/uploads→ backend:8000
  backend ─→ postgres:5432    backend ─→ redis:6379
```

## 4. First-time deployment

```bash
sudo mkdir -p /opt/apps/alphasync-real
sudo chown "$USER" /opt/apps/alphasync-real
git clone <repo> /opt/apps/alphasync-real     # backend/ + frontend/ must land here
cd /opt/apps/alphasync-real

cp .env.example .env        # fill in real secrets
# place firebase-credentials.json here if using a file

bash deployment.sh
```

`deployment.sh` builds + starts the stack, waits for backend health, installs
**only** this app's nginx site, and reloads nginx if the config tests clean.

---

## 5. Updates (CI/CD)

`.github/workflows/deploy-alphasync-real.yml` runs on push to `main`:

```
ssh server → cd /opt/apps/alphasync-real
           → git pull (reset --hard origin/main)
           → docker compose pull
           → docker compose -p alphasync-real up -d --build
           → docker image prune -f
```

Local equivalent: `bash update.sh` (records last-good image IDs first).

**Required GitHub secrets:** `SERVER_HOST`, `SERVER_USER`, `SERVER_SSH_KEY`.

---

## 6. Rollback

```bash
bash rollback.sh            # revert one git commit + rebuild
bash rollback.sh --images   # restart last-known-good images (no rebuild)
```

Data volumes are never touched — Postgres/Redis/uploads survive rollback.

---

## 7. Secrets

All secrets come from `.env` (never hardcoded): DB password, `JWT_SECRET_KEY`,
`BROKER_ENCRYPTION_KEY`, Zebu/Alice Blue broker creds, Firebase, Twilio, SMTP,
Grok/xAI. Frontend Firebase (public client) values are build args baked into the
bundle. `.env` and `firebase-credentials.json` are gitignored.

---

## 8. Guarantees for the shared server

- No container, network, or volume of another app is referenced anywhere.
- No `--remove-orphans`, no global prunes.
- Every other application is untouched by every script and the workflow. Future
  apps follow this same template with their own project, network, volumes,
  ports, and nginx site.
